# Phase 1 insurer workshop

Use one cyber product and one application or renewal scenario. The sample settings are discussion defaults for the fictional case.

| Decision | Sample setting | Confirm with the insurer |
| --- | --- | --- |
| Case type | Renewal | First workflow, case owner, submission deadline |
| Evidence checklist | MFA, access review, backup coverage, restore test | Required fields, scope, acceptable sources, freshness |
| Restore scope | Order processing service | Which dependencies and functional checks must be included |
| Recovery targets | 240 minutes to restore, 60 minutes of data age | Measurement start and end, data-loss reference time, pass criteria |
| Evidence review | Underwriter and delegated technical reviewer | Who verifies each requirement and who can approve exceptions |
| Follow-up | Request a fix and retest, keep access review open | Who receives requests, expected response, escalation and closure criteria |
| Decision record | Record rationale and exact evidence versions | Required fields, decision authority, and export destination |

## Pilot acceptance

- The underwriter can identify the missed recovery target and locate the source record.
- The reviewer can explain how the retest meets the defined recovery targets.
- The case still shows the independent access-review gap after the retest passes.
- The insurer agrees on the checklist, responsibilities, and the evidence needed to close the case.
